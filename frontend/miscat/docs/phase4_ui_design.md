# Phase 4 UI設計 - チャンネル & DM

## 概要

Phase 4では、リアルタイムメッセージング機能（チャンネル & DM）のUIを実装します。
本ドキュメントでは、画面設計、コンポーネント設計、データフロー設計を定義します。

### 設計方針
- **統一性**: 既存UI（Wiki、タグ、検索）と一貫したデザイン
- **shadcn/ui**: 全てshadcn/uiコンポーネントを使用
- **リアルタイム**: WebSocketによるリアルタイム更新
- **フォーマル**: v3仕様の「フォーマルなデザイン」を維持

## 3. データフロー設計

### 3.1 WebSocket接続管理

#### 3.1.1 WebSocket Context
**ファイル**: `context/WebSocketContext.tsx`

**機能**:
- WebSocket接続管理（グローバル）
- 接続/切断処理
- メッセージ受信リスナー登録
- 再接続ロジック

**実装パターン**:
```typescript
const WebSocketProvider = ({ children }) => {
  const [socket, setSocket] = useState<WebSocket | null>(null);
  const [isConnected, setIsConnected] = useState(false);

  useEffect(() => {
    // WebSocket接続
    const ws = new WebSocket('ws://backend:8000/ws');

    ws.onopen = () => setIsConnected(true);
    ws.onclose = () => setIsConnected(false);
    ws.onerror = (error) => console.error(error);

    setSocket(ws);

    return () => ws.close();
  }, []);

  return (
    <WebSocketContext.Provider value={{ socket, isConnected }}>
      {children}
    </WebSocketContext.Provider>
  );
};
```

#### 3.1.2 メッセージ受信
- WebSocketContextからsocketを取得
- `socket.onmessage`でメッセージ受信
- 受信したメッセージをstateに追加
- 自動スクロール（最新メッセージが表示される）

#### 3.1.3 メッセージ送信
- `socket.send(JSON.stringify({ type: 'message', content, channel_id }))`
- 送信成功後、楽観的UI更新（すぐにメッセージを表示）
- サーバーからの確認メッセージを待つ

### 3.2 リアルタイムメッセージ受信

#### フロー
```
1. WebSocket接続確立
2. チャンネル/DM詳細ページで購読（subscribe）
3. 新着メッセージ受信
   → state更新
   → MessageList再レンダリング
   → 自動スクロール
4. ページ離脱時に購読解除（unsubscribe）
```

#### 実装例
```typescript
useEffect(() => {
  if (!socket) return;

  const handleMessage = (event) => {
    const data = JSON.parse(event.data);

    if (data.type === 'new_message' && data.channel_id === channelId) {
      setMessages(prev => [...prev, data.message]);
    }
  };

  socket.addEventListener('message', handleMessage);

  // チャンネル購読
  socket.send(JSON.stringify({ type: 'subscribe', channel_id: channelId }));

  return () => {
    // 購読解除
    socket.send(JSON.stringify({ type: 'unsubscribe', channel_id: channelId }));
    socket.removeEventListener('message', handleMessage);
  };
}, [socket, channelId]);
```

### 3.3 メッセージ送信フロー

```
1. ユーザーがメッセージ入力
2. 送信ボタンクリック / Enter押下
3. バリデーション（文字数チェック）
4. WebSocket送信
   socket.send({ type: 'message', content, channel_id })
5. 楽観的UI更新（即座にメッセージ表示）
6. サーバーから確認メッセージ受信
   → メッセージIDを更新
   → エラーがあればToast表示
```

#### 3.4.1 メッセージキャッシュ
- ローカルstateにメッセージを保持

## 6. リスクと対策

### 6.1 WebSocket接続の安定性
**リスク**: ネットワーク不安定時の切断

**対策**:
- 自動再接続ロジック実装
- 接続状態表示（オンライン/オフライン）
- オフライン時のメッセージキューイング（将来実装）

### 6.2 メッセージの順序保証
**リスク**: 複数ユーザーの同時送信時の順序

**対策**:
- サーバー側タイムスタンプを信頼
- クライアント側でタイムスタンプソート

### 6.3 パフォーマンス
**リスク**: 大量メッセージの表示遅延

**対策**:
- 仮想スクロール（react-window）の検討
- ページネーション実装
- 初期表示件数を制限（50件）
