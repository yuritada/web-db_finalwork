# ログインページ

**パス**: `/login`
**ファイル**: `app/(auth)/login/page.tsx`
**認証**: 不要（誰でもアクセス可能）

---

## 📋 概要

既存ユーザーがアカウント情報を入力してMiscatにログインするためのページです。ユーザー名とパスワードを使用した認証を行い、成功後はトップページ（`/`）にリダイレクトされます。

---

## 🎯 主な機能

### 1. ログインフォーム
- **ユーザー名入力**: ユーザー名を入力
- **パスワード入力**: パスワードを入力（マスク表示）
- **ログインボタン**: 認証リクエストを送信

### 2. 入力バリデーション
- **必須項目チェック**: ユーザー名とパスワードが入力されているか確認
- **エラー表示**: バリデーションエラーやログイン失敗時にエラーメッセージを表示

### 3. 自動リダイレクト
- **ログイン成功**: トップページ（`/`）へリダイレクト
  - トップページで認証状態を確認し、メインダッシュボード（`/main`）へ自動遷移
- **未認証ユーザー**: ログインページを表示

### 4. ローディング状態
- **ログイン中表示**: ボタンテキストが「ログイン中...」に変化
- **フォーム無効化**: 送信中は入力フィールドとボタンを無効化

---

## 🔒 制限事項

### アクセス制限
- **制限なし**: 誰でもアクセス可能
- **認証済みユーザー**: アクセス可能だが、通常は使用しない

### 機能制限
- **OAuth認証なし**: ユーザー名/パスワード認証のみ対応
- **パスワードリセットなし**: パスワード忘れ機能は未実装

## 🔌 接続先API

### 使用API

#### 1. ログインAPI
- **エンドポイント**: `POST /auth/token`
- **リクエスト**:
  ```typescript
  {
    username: string;
    password: string;
  }
  ```
- **レスポンス**:
  - `200 OK`: ログイン成功（トークンはHttpOnly Cookieに設定）
  - `401 Unauthorized`: 認証失敗（ユーザー名またはパスワードが間違っている）
  - `422 Unprocessable Entity`: バリデーションエラー

### API関数
```typescript
// lib/api.ts
await login(username, password);
```

## 🔧 実装詳細

### 状態管理
```typescript
const [username, setUsername] = useState('');
const [password, setPassword] = useState('');
const [error, setError] = useState('');
const [isLoading, setIsLoading] = useState(false);
```

### フォーム送信処理
```typescript
const handleSubmit = async (e: React.FormEvent) => {
  e.preventDefault();
  setError('');
  setIsLoading(true);

  try {
    // バリデーション
    if (!username || !password) {
      setError('ユーザー名とパスワードを入力してください');
      setIsLoading(false);
      return;
    }

    // ログイン実行
    await login(username, password);

    // ログイン成功後、ホームページへリダイレクト
    router.push('/');
  } catch (err: unknown) {
    // エラーハンドリング
    if (err instanceof Error) {
      setError(err.message || 'ログインに失敗しました');
    } else {
      setError('ログインに失敗しました');
    }
  } finally {
    setIsLoading(false);
  }
};
```

## 📝 備考

### 開発時の注意
- ログイン成功後は必ずトップページ（`/`）へリダイレクト
- エラーメッセージは具体的に表示（セキュリティ上、詳細すぎる情報は避ける）
- パスワードフィールドは必ずマスク表示（type="password"）

### テスト方法
1. **正常系**: 有効なユーザー名とパスワードでログイン
   - 例: `student1@test.com` / `test1234`（テストアカウント）
2. **異常系**:
   - 空欄でログインボタンをクリック → バリデーションエラー
   - 間違ったユーザー名/パスワード → 認証エラー

### セキュリティ
- パスワードはHTTPSで送信（本番環境）
- トークンはHttpOnly Cookieで管理（XSS攻撃対策）
- CSRF対策は未実装（Phase 5で対応予定）
