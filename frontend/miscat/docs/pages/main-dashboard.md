# メインダッシュボード

**パス**: `/main`
**ファイル**: `app/(main)/page.tsx`
**認証**: 必須（ログインユーザーのみアクセス可能）

---

## 📋 概要

認証済みユーザーがログイン後に表示されるメインダッシュボードページです。ユーザー情報、各機能の概要、お知らせなどを表示します。サイドバーナビゲーション付きのレイアウトで、他の機能ページへの起点となります。

---

## 🎯 主な機能

### 1. ウェルカムメッセージ
- **パーソナライズ表示**: 「ようこそ、{ユーザー名}さん」と表示
- **説明文**: Miscatダッシュボードの概要説明

### 2. アカウント情報カード
- **ユーザー名**: 現在ログイン中のユーザー名
- **メールアドレス**: 登録メールアドレス
- **区分**: ユーザーカテゴリ（学生、教授、准教授、講師、事務）
- **学籍番号**: 学生の場合のみ表示
- **学部・所属**: 登録している場合のみ表示

### 3. 機能紹介カード
4つの主要機能をカード形式で表示：
- **Wiki**: 知識共有のためのWikiページ作成・編集
- **チャンネル**: テーマ別のチャンネルでメッセージ共有
- **タグ**: 興味のあるタグをフォローして情報整理
- **DM**: 1対1のダイレクトメッセージ

各カードには「準備中」バッジが表示されています（Phase 2以降で実装予定）。

### 4. お知らせセクション
- **進捗情報**: プロジェクトのフェーズ進捗を表示
  - Phase 1完了: ユーザー認証機能
  - Phase 2準備中: Wiki、チャンネル、タグ、DM機能

### 5. サイドバーナビゲーション
- **メインナビゲーション**: 他のページへのリンク（Wiki、タグ、検索、チャンネル、DM）
- **ユーザーメニュー**: プロフィール、設定、ログアウト

---

## 🔒 制限事項

### アクセス制限
- **認証必須**: 未認証ユーザーはアクセス不可
- **自動リダイレクト**: 未認証状態でアクセスした場合、ログインページへリダイレクト

### 機能制限
- **機能カードのリンクなし**: 現在は情報表示のみ（Phase 2以降でリンク化予定）
- **お知らせの静的表示**: データベースから取得せず、コード内でハードコーディング

---

## 🔌 接続先API

### 使用API

#### 1. 認証確認API
- **エンドポイント**: `GET /auth/me`
- **レスポンス**:
  ```typescript
  {
    id: string;
    username: string;
    email: string;
    kategori: string;
    gakuseki_bango?: string;
    faculty?: string;
  }
  ```
- **使用箇所**: AuthContext（自動的に呼ばれる）

### コンテキスト
```typescript
const { user } = useAuth();  // AuthContextからユーザー情報を取得
```

### UIコンポーネント

#### 1. ウェルカムメッセージ
- **タイトル**: "ようこそ、{ユーザー名}さん"
- **スタイル**: 3xl、太字、グレー900
- **説明文**: グレー600

#### 2. アカウント情報カード
- **使用コンポーネント**: `@/components/ui/card`
- **レイアウト**: 2列グリッド（モバイルでは1列）
- **表示項目**:
  - ユーザー名（必須）
  - メールアドレス（必須）
  - 区分（必須）
  - 学籍番号（条件付き）
  - 学部・所属（条件付き）

#### 3. 機能紹介カード
- **使用コンポーネント**: `@/components/ui/card`
- **レイアウト**: 4列グリッド（タブレット: 2列、モバイル: 1列）
- **各カード内容**:
  - タイトル（Wiki、チャンネル、タグ、DM）
  - 説明文
  - 「準備中」バッジ（黄色）

#### 4. お知らせカード
- **使用コンポーネント**: `@/components/ui/card`
- **レイアウト**: リスト形式
- **各お知らせ項目**:
  - ステータスドット（完了: 青、準備中: グレー）
  - タイトル
  - 説明文

## 📝 備考

### 開発時の注意
- AuthContextの`user`オブジェクトを必ず使用
- 未実装の機能カードにはリンクを設定しない
- レスポンシブデザインを考慮（グリッドのブレークポイント）

### テスト方法
1. **認証済み**: ログイン後、メインページにアクセス
2. **未認証**: ログアウト状態で `/main` にアクセス → ログインページへリダイレクト確認
3. **ユーザー情報表示**: 各区分のユーザーで表示内容が適切か確認

### 今後の拡張予定
- 機能カードにリンクを追加（Phase 2）
- お知らせ機能の動的化（データベース連携）
- ダッシュボードのカスタマイズ機能
